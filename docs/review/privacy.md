# LifeOS v0.12.0 review: AI boundary, privacy, data integrity

Reviewer scope: src/core/ai.js, memory.js, metrics.js, goals.js, revenue.js, activities.js, social.js, wellbeing.js, learning.js, home.js, admin.js, csv.js, and the parts of store.js and priv.js they use; the app.js call sites that feed them. Verified from source and by running code, not from docs or test names.

Proof tests: test/review-privacy.test.mjs. Tests 1 to 5 are checks that pass. Each `PV-n` test fails today and passes once PV-n is fixed. Note: `npm test` runs every file in test/, so the suite now reports 10 failures until these are fixed or the file is moved.

## Checked and found sound

- Prompts (levels 1, 2, 3), weekly digest, rules insights and audit entries: with a marker (containing spaces) in every free-text field of every main collection, the ledger import (line, category, description), extra private records, a person and a line of work moved in with children, and a wellbeing check-in with a note, no marker appears, with the vault open and closed. Digest numbers are identical for the open view and the main state (`mainOnly`), so private records never count (test 1).
- Body metrics: weight and body fat values and the weight change never reach a prompt; weight and body fat goals are left out of goal counts; the approved weight rules insight is excluded from level 1 and 2 context.
- Wellbeing: absent from the digest, rules, the domain list in the system prompt, `parseResponse`, `propose` and lessons; earlier approved wellbeing insights are never sent; CSV import refuses it; a public goal cannot use a wellbeing metric (validateState).
- AI never has the final say: `parseResponse` returns only domain and text; `propose` always writes `proposed`; only `memory.decide` sets `approved`, and only app.js:1080 (a tap) calls it with `approved`. Backup restore offers to demote approvals.
- `ai.complete`: closes the private vault first, local URL whitelist, 20 s timeout, 1 MB streamed cap, `credentials: omit`, `redirect: error`, no referrer; errors never echo the key, provider text or HTTP body (test 2).
- Thrown errors from validateEntry, validateState, activities, social, learning, wellbeing, goals, parseResponse, ledger rejects and priv.open never echo typed text, secrets or a body value (test 2).
- Nothing auto-posts: recurring confirm, carry-over, next maintenance, next renewal, activity expense, mark received, write off, roll over, starter checklist and social convert are each called only from a tap handler in app.js.
- Money: integer cents per entry everywhere; per-line plus Unassigned equals `monthView` and `totalsIn` for 14 months and every period type with sub-cent values, expected and written-off income, archived, parent and dangling links (test 4). Margin is null at zero revenue and exact basis points otherwise. Activity cost reaches Money once, only on a tap, and edit, skip and delete never double count (test 5). Activity and expense move into the vault together.
- Date maths: calendar-day arithmetic on strings (Date.UTC as a day counter); tests 1 to 5 give the same result under TZ=Pacific/Auckland and America/New_York. Month end, Feb 29 important dates and year end windows behave as specified (apart from PV-4).
- Divide by zero and NaN: goals progress and pace, learning progress, activities per hour and averages, admin custom run-rate, habit rate, wellbeing averages and revenue margin all guard their divisor.
- CSV: parser is linear with byte, row, column and cell caps; export neutralises `= + - @`, tab, CR, LF in every column and skips private records. No RegExp is built from user input anywhere in src (only fixed patterns in admin.js); social and learning search use substring matching.
- Secrets guard: linear on 2,000-character inputs (1,000 calls in about 80 ms); folds full-width, other-script digits, invisible and dash characters.
- Social name matching: NFKC, invisible characters, whitespace and case folded; a name shared by two people maps to nobody; a log entry and an activity on the same day count once.
- References and cycles: project parents one level, goal parents strictly longer horizon plus a loop check, priv closure uses a seen set; dangling links are dropped and the record kept.
- Performance at caps (1,000 people with 50 facts, 20,000 contacts, 5,000 activities with 10 people): weekly digest 160 ms, 8-week social series 285 ms, search 32 ms, validateState 100 ms.
